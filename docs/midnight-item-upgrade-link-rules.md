# Midnight 装备最高装等链接规则

本文定义 WoWLook 以后处理“将客户端导出的装备展示为本赛季最高可获得版本”时必须遵守的规则。

它参考本机 KeystoneLoot 2.11.1 的 S2 数据和链接构造方式，但 **KeystoneLoot 不是最终真值来源**。最终结果始终以当前 WoW 客户端实际解析出的物品链接与说明框为准。

## 范围与边界

- 普通地下城/团本装备：可采用本规则重建候选最高版本链接。
- 套装：继续使用 WoWLookTierExport 的独立采集与验证流程。KeystoneLoot 的催化剂表只有每职业 5 件核心件 ID，不包含 2/4 件效果文本、外观件全集或完整说明框，不能替代套装采集。
- 制造装备、非装备、玩具、坐骑、固定装等物品：不能套用通用升级链路；必须按各自规则和客户端预览验证。
- 任意无法读取基础装等、无法构造链接或说明框未加载的物品：显式标为未验证，绝不回退成旧赛季或基础模板数据。

## 数据来源优先级

1. WoWLook 当前客户端预检导出：物品 ID、来源副本/首领、职业/专精、原始链接、中文说明框、基础展示数据。
2. 本赛季规则清单：目标装等、轨道 Bonus ID、固定来源/特殊物品例外。
3. 客户端 API：`C_Item.GetDetailedItemLevelInfo` 与 `C_TooltipInfo.GetHyperlink` 对候选链接的实际结果。
4. KeystoneLoot：仅作为候选装备清单、来源映射和升级轨道参考。

规则清单和最终 JSON 必须记录 `dataVersion`、`clientBuild` 与来源证据；不同 Build 的结果不得静默混用。

## 标准候选链接构造

对已验证为可升级的装备，按下列顺序生成候选链接：

1. 用物品 ID 从客户端读取 `baseItemLevel`；不可用则停止。
2. 从赛季规则选择该来源的目标轨道与目标装等。例如当前 KeystoneLoot S2 参考表的地下城“大秘境宝库”最高档和团本 Mythic 最高档均为 **334**，轨道 Bonus ID 为 **12854**。这只是候选值，发布前必须由当前客户端验证。
3. 计算 `levelDiff = targetItemLevel - baseItemLevel`。
4. 通过“装等差值 → Bonus ID”映射取得装等修正 Bonus ID。该映射是游戏数据，不可假定 `Bonus ID` 与装等相等，也不可跨赛季硬抄。
5. 组合 Bonus ID：
   - 装等修正 Bonus ID；
   - 目标升级轨道 Bonus ID；
   - 已验证需要保留的物品专用 Bonus ID；
   - 已验证需要保留的部位或品质 Bonus ID；
   - 绝不加入角色当前的附魔、宝石或收藏偏好。
6. 使用正确的专精 ID 与玩家等级构造 `item:` 超链接；专精未知时不得构造最终版本。
7. 让客户端加载候选链接，读取详细装等和完整说明框。
8. 只有全部验证通过时，才将候选链接作为导出装备的 `finalLink`。

链接模板（字段位置必须由客户端版本验证）如下：

```text
item:<itemId>:<enchant>:<gem1>:<gem2>:<gem3>:<gem4>::<playerLevel>:<specId>::<bonusCount>:<bonusIds...>
```

## 必须通过的验证

每件最终装备至少满足：

- 候选链接解析出的物品 ID 等于原物品 ID；
- 说明框装等与 `C_Item.GetDetailedItemLevelInfo` 的有效装等一致；
- 有目标装等规则时，实际装等严格等于目标装等；
- 链接包含规则要求的每一个 Bonus ID；
- 装备栏位与来源版本一致；
- 物品名称、属性、特效和原始说明框来自候选链接的当前客户端解析结果；
- 输出写入 `sourceVersion`、`rebuildTarget`、`matchedRule`、`finalLink`、`finalTooltipItemLevel` 与 `clientBuild`。

任何一项失败都必须写入失败原因，例如 `base_item_level_unavailable`、`bonus_mapping_missing`、`target_item_level_mismatch`、`required_bonus_missing` 或 `tooltip_unavailable`。

## 不可泛化的例外

以下项目必须在赛季规则文件中单独声明并以客户端实测确认：

- 固定难度/固定装等团本掉落；
- 特殊武器、饰品、项链、戒指和稀有掉落；
- 虚空核心/类似赛季机制；
- 不可升级装备；
- 制造业配方、追加材料和最终预览；
- 套装核心件、外观件与 2/4 件效果。

不要把 KeystoneLoot 当前实现中“始终加入品质 Bonus 1674”或“戒指/项链加入 13534”的做法当作永久通用规则。它们只能在当前 S2 客户端预检证明必要时，作为显式规则写入清单。

## 发布前检查

1. 从游戏导出普通装备预检数据。
2. 将 KeystoneLoot 清单仅用于比对装备集合和来源，不直接发布其数据。
3. 将每一种来源/轨道的目标装等与 Bonus ID 写入已审核的赛季规则文件。
4. 用所有最终候选链接在同一客户端 Build 上逐件验证。
5. 阻止任意预检数据、未验证物品或 S1 字段进入 `data-12.1-s2`。
6. 套装和制造业在各自验证完成前保持独立、不可发布状态。
# S2 套装 ID 发现边界

S2 的 13 职业 × 9 件套装必须由客户端幻化套装接口发现：核心五件的 Catalyst ID 只用于定位套装，插件必须将 `物品 ID → 幻化来源 ID → 套装来源 ID → 物品 ID` 的证据一并保存。幻化来源或外观 ID 不能直接作为小程序装备 ID。每个职业只有在头、肩、胸、腕、手、腰、腿、脚、背九个部位各得到一件真实物品且五个核心 ID 均在其中时，才能导出完整的预检装备记录。

预检记录逐件从客户端读取名称、链接、装等、属性、特效与说明框；它们不是仅供展示的外观数据。最高装等链接和属性仍须按下文规则独立验证后才能正式发布。
