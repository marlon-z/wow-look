# WCL COS `data-12.1` 迁移设计

## 目标

主小程序的“排行榜配装”恢复从腾讯云 COS 按需读取 WCL 预设，并切换至新的、唯一的 WCL 数据目录：

```text
wcl-presets/data-12.1/{classKey}/{specId}/
```

数据使用 WCL 的低频分批轮转持续更新；小程序在新目录有第一批数据后即开放，不等待全职业完成。第二账号小程序不在本次范围内。

## 数据流

```text
WCL API → GitHub Actions（最旧优先，每小时 3 专精）
        → COS wcl-presets/data-12.1
        → 主小程序按专精/分类按需读取
```

每个专精的 JSON 包含 3 个大秘境档位和 2 组史诗团本数据。小程序读取 `index.json` 后再读取用户选中的分类文件，并在请求 URL 加时间戳避免 CDN 或客户端缓存造成数据滞后。

## 发布策略

1. 把生成器、最旧优先查询和上传路径统一切至 `data-12.1`。
2. 保持 GitHub Actions 每小时只更新 3 个最旧专精，避免耗尽 WCL 免费 API 配额。
3. 主小程序恢复 COS 读取并立即开放入口。尚未轮转到的职业/专精显示既有的“当前暂无排行榜配装”，不读取旧目录。
4. 对新目录生成的每份预设执行装备映射审计；完成后持续随每轮更新验证。
5. 在新路径读取和映射稳定后，删除 COS 的 `wcl-presets/data-4.4.x`，并移除代码中旧 WCL 目录引用。

## 装备映射审计

对每个 WCL 预设的槽位执行以下检查：

- `itemId` 必须存在于主小程序当前 12.1 本地装备库；
- 物品槽位必须与 WCL 槽位兼容；
- 制造业随机绿字、附魔和宝石字段必须能保留并正常展示；
- 生成审计报告，按职业、专精、数据文件和物品 ID 列出缺失或异常项。

发现缺失物品时，套用功能继续以现有的“未知装备”兜底，审计报告作为补齐本地装备库的依据；不会静默把错误物品映射到其他装备。

## 故障处理与验证

- COS 请求失败或 JSON 无效时返回空数据，由现有页面提示加载失败或暂无预设；
- 不使用旧目录回退，避免新旧赛季装备混用；
- 自动化仍在全量生成结果为 0 时拒绝上传；
- 测试覆盖新路径、开放状态、缓存参数、请求失败，以及装备映射审计；
- 发布前以真实 COS 中已更新的专精验证索引、列表、套用、天赋代码和附魔宝石。
