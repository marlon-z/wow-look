# 原生文字 Logo 预览设计

## 目标

提供一个独立的微信小程序原生页面，同时展示三套“艾泽配装”文字 Logo 方案，供用户在真机上比较；在用户选定前不修改首页现有 Logo。

## 范围与入口

- 新增主包页面 `pages/logo-preview/logo-preview` 并在 `app.json` 注册；可在微信开发者工具通过该页面路径直接打开。
- 预览页仅用于设计验收，不从首页增加生产入口，也不修改 `pages/index/index` 的现有图片 Logo。
- 每套方案包含标题“艾泽配装”、必要的几何装饰与副标题“当前赛季毕业装速查”，置于与首页一致的深色背景中。

## 三套方案

1. **锻造铭牌（推荐）**：居中大号金色标题、双层深色投影、上方菱形徽记、标题两侧水平金线；保留现有魔兽风格的庄重感。
2. **简洁工具**：左侧小菱形与细竖线，右侧紧凑标题与说明；层级更清楚、占用高度更小，偏现代工具产品。
3. **符文印记**：标题置于双层细边框内，以四角菱形和短横线组成对称框架；视觉最具游戏感，但信息密度最高。

## 原生兼容边界

- 只使用 WXML 的 `view`、`text`、`button`，以及 WXSS 的 Flex 布局、边框、线性渐变、`text-shadow`、`box-shadow` 和 `transform`。
- 不使用图片 Logo、SVG、Canvas、网页专用 DOM/CSS、远程字体或运行时加载的字体文件。
- 中文字形使用小程序宿主设备的系统字体；通过字号、字重、字距、金色系颜色和阴影形成视觉层次，而不依赖某一台设备特有的花体字体。

## 页面结构

- 公共页面标题、说明和返回首页按钮。
- 三个语义清晰的方案卡片：各自封装标记、标题、装饰线和副标题，样式命名以 `logo-preview-<variant>` 为前缀，避免和现有首页类冲突。
- 页面不保存选择结果、不写本地存储、不改变导航或首页状态；用户确认方案后另行将对应 WXML/WXSS 合入首页。

## 验证

- 新增静态回归测试，检查页面已在 `app.json` 注册、三个方案标题和副标题存在、页面不含 `<image>`，且只使用上述原生组件。
- 运行现有本地数据包测试，确认预览页没有引入媒体资源或突破主包硬限制。
- 在微信开发者工具和真机打开 `pages/logo-preview/logo-preview`，检查三个方案中文文字完整、没有字体加载错误，且小屏上不溢出。
