# 制造业装备导出插件设计

## 目标

新增独立的游戏内插件 `WoWLookCraftExport`，从当前版本的制造订单界面收集可制作战斗装备。正式数据只包含订单系统显示 `246+` 且最高制造结果实际达到 285 物品等级的装备。

插件只负责采集和验证，不修改现有地下城、团本、套装导出链路，也不修改小程序。

## 数据口径

候选装备必须同时满足：

- 来自当前制造订单搜索结果；
- 订单列表的装等范围显示为 `246+`；
- 输出物品属于武器或可装备护甲；
- 部位属于玩家战斗装备栏位；
- 使用最高制造条件后，游戏内实际说明框显示物品等级 285。

专业工具、专业配饰、消耗品、玩具、纯外观、固定低装等装备和无法验证的装备不进入正式数据。

## 采集方式

插件采用“界面候选采集 + 说明框真值验证”两阶段流程。

1. 玩家打开制造订单并执行搜索。
2. 插件从当前订单搜索结果读取配方、输出物品和界面装等文本。
3. 显示 `246+` 的装备进入候选池，其他结果记录排除原因。
4. 插件读取当前配方预览输出的物品链接和说明框。
5. 只有说明框解析到 285 物品等级时，装备才进入正式导出集合。

如果客户端 API 无法直接给出最高材料预览，插件不得用基础物品编号伪造成功结果。该候选应保持 `pending`，由玩家在订单详情中配置最高材料后再次采集。

## 随机属性

随机属性数量以说明框文本为准，不预设为两条：

- 无“随机属性”行：固定绿字；
- 一条“随机属性1”：配装时选择一种属性；
- 两条“随机属性1/2”：配装时选择两种属性。

导出同时保留每个随机属性位置的实际数值。固定副属性与随机属性位置分开保存，避免后续统计时把可选属性误认为装备已经拥有的属性。

## 导出结构

SavedVariables 顶层包含：

- 插件版本、客户端版本、导出时间；
- 扫描与验证统计；
- `items`：通过285验证的正式装备；
- `candidates`：尚待验证的246+候选；
- `rejected`：不符合条件的结果及原因；
- `errors`：API或说明框读取错误。

正式装备至少保存：

- `recipeId`、`itemId`、名称、图标和专业；
- 部位、甲种或武器类型、品质、绑定方式；
- 物品等级、主属性、耐力、固定副属性；
- 随机属性数量及各位置数值；
- 装备/使用特效、插槽、唯一装备标记；
- 实际预览物品链接和完整原始说明框。

## 失败策略

插件采用失败关闭原则：

- 不是 `246+`：排除；
- 不是战斗装备：排除；
- 预览低于285：排除；
- 无法读取最高预览：保持待验证；
- 说明框读取或解析失败：记录错误，不进入正式数据。

不得把基础模板、推算装等或人工拼接出的未验证链接当成正式结果。

## 游戏内流程

插件提供命令：

- `/wowcraft scan`：扫描当前制造订单搜索结果；
- `/wowcraft capture`：采集当前打开的订单详情预览；
- `/wowcraft status`：显示通过、待验证、排除和错误数量；
- `/wowcraft reset`：清空本插件采集数据；
- `/wowcraft help`：显示操作说明。

玩家按专业或分类搜索订单列表，运行扫描；随后逐个打开待验证候选，配置最高制造材料并运行采集。数据累计写入账号级 SavedVariables，可跨角色、跨专业继续采集。

## 验收标准

- 能识别截图所示 `246+` 候选；
- 能从说明框区分固定属性、一条随机属性和两条随机属性；
- 只有实际预览为285的装备进入 `items`；
- 固定低装等和非战斗装备不会进入正式数据；
- 失败结果有明确状态和原因；
- 不影响 `WoWLookExport3`、`WoWLookTierExport` 和小程序现有数据。
