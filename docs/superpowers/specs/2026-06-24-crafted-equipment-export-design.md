# 制造业装备导出插件设计

## 目标

新增独立的游戏内插件 `WoWLookCraftExport`，从当前版本制造订单目录收集可制作战斗装备。候选发现不写死起始装等，并以扫描结果中的最高起始装等识别当前赛季；赛季目标装等与公共制造 Bonus ID 独立配置。正式数据只包含重建链接经游戏说明框验证达到配置目标装等的装备。

插件只负责采集和验证，不修改现有地下城、团本、套装导出链路，也不修改小程序。

## 数据口径

候选装备必须同时满足：

- 来自当前制造订单搜索结果；
- 订单列表的装等范围显示为“某个装等+”；
- 输出物品属于武器或可装备护甲；
- 部位属于玩家战斗装备栏位；
- 使用最高制造品质重建链接后，游戏内实际说明框达到赛季配置的目标装等。

专业工具、专业配饰、消耗品、玩具、纯外观、固定低装等装备和无法验证的装备不进入正式数据。

## 采集方式

插件采用“后台候选采集 + 配置驱动链接重建 + 说明框真值验证”流程。

1. 插件直接调用制造订单目录 API，无需玩家打开订单界面。
2. 插件从当前版本订单选项读取配方、输出物品和装等字段。
3. 显示“装等+”的装备进入候选池，其他结果记录排除原因。
4. 插件取得每个配方最高制造品质的基础输出链接。
5. 插件保留原链接的制造品质与随机属性 modifier，并用赛季公共制造 Bonus ID 替换基础缩放 Bonus ID。
6. 游戏接口读取重建链接的说明框；只有实际装等等于配置目标值的装备才进入正式导出集合。

重建链接用于采集目标装等属性，不代表实际订单材料组合。如果客户端 API 无法解析链接，或说明框装等不等于配置目标值，该候选保持 `configured_maximum_unverified`，可由玩家在订单详情中配置最高材料后用手动命令补采。

## 随机属性

随机属性数量以说明框文本为准，不预设为两条：

- 无“随机属性”行：固定绿字；
- 一条“随机属性1”：配装时选择一种属性；
- 两条“随机属性1/2”：配装时选择两种属性。

导出同时保留每个随机属性位置的实际数值。固定副属性与随机属性位置分开保存，避免后续统计时把可选属性误认为装备已经拥有的属性。

## 导出结构

SavedVariables 顶层包含：

- 插件版本、客户端版本、导出时间；
- 扫描与验证统计；
- `items`：通过动态最高装等验证的正式装备；
- `candidates`：尚待验证的“装等+”候选；
- `rejected`：不符合条件的结果及原因；
- `errors`：API或说明框读取错误。

正式装备至少保存：

- `recipeId`、`itemId`、名称、图标和专业；
- 部位、甲种或武器类型、品质、绑定方式；
- 物品等级、主属性、耐力、固定副属性；
- 随机属性数量及各位置数值；
- 装备/使用特效、插槽、唯一装备标记；
- 实际预览物品链接和完整原始说明框。

## 失败策略

插件采用失败关闭原则：

- 不是“装等+”：排除；
- 不是战斗装备：排除；
- 重建链接不是配置目标装等：保持待验证；
- 无法读取目标链接：保持待验证；
- 说明框读取或解析失败：记录错误，不进入正式数据。

不得把未经游戏说明框验证的重建链接当成正式结果。

## 游戏内流程

插件提供命令：

- `/wowcraft scan`：无需打开界面，扫描全部当前版本订单选项并按赛季配置验证最高装等；
- `/wowcraft capture`：采集当前打开的订单详情预览；
- `/wowcraft status`：显示通过、待验证、排除和错误数量；
- `/wowcraft reset`：清空本插件采集数据；
- `/wowcraft help`：显示操作说明。

正常流程只需登录后运行一次扫描。只有自动探测失败的候选才需要打开订单详情手动补采。数据累计写入账号级 SavedVariables，可跨角色、跨专业继续采集。

## 验收标准

- 能识别当前版本界面所示“装等+”候选，不依赖具体起始数字；
- 能从说明框区分固定属性、一条随机属性和两条随机属性；
- 只有重建链接经说明框确认达到赛季目标装等的装备进入 `items`；
- 固定低装等和非战斗装备不会进入正式数据；
- 失败结果有明确状态和原因；
- 不影响 `WoWLookExport3`、`WoWLookTierExport` 和小程序现有数据。
