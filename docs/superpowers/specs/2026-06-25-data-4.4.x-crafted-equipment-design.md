# 4.4.x 制造业装备数据设计

## 目标

创建独立的 `cos-upload/data-4.4.x` 数据集，以现有 `cos-upload/data-4.3.x` 为底座，并注入游戏内 `WoWLookCraftExport` 已验证的当前版本制造业装备。保留 `data-4.3.x` 不变，不在本步骤修改小程序交互。

## 数据来源

- 底座数据：`cos-upload/data-4.3.x`
- 制造业导出：`E:/World of Warcraft/_retail_/WTF/Account/513648058#1/SavedVariables/WoWLookCraftExport.lua`

制造业导出必须满足：

- `accepted = 98`
- `pending = 0`
- `failed = 0`
- 普通制造装备为 285
- 武器、饰品、盾牌、副手法器为 295

## 注入口径

制造业装备作为独立来源进入每个职业数据：

- instance：`manufacturing`
- instance 名称：`制造业`
- encounter：`crafted-equipment`
- encounter 名称：`制造业装备`
- `sourceType = "crafted"`

职业可见性按装备可用性分配：

- 布/皮/锁/板护甲按职业护甲类型分配；
- 项链、戒指、披风、饰品全职业；
- 武器、盾牌、副手法器按小程序当前武器布局规则可使用的专精分配；
- 没有任何适用专精的装备不进入该职业文件。

## 随机属性约定

固定绿字装备直接写入 `stats.secondary`，沿用现有筛选和配装统计逻辑。

带“随机属性”的制造业装备不得把四种绿字展开进 `stats.secondary`，否则当前包含/排除筛选会误判。它们保留实际随机槽位数值，并写入独立字段：

```js
crafting: {
  randomAttributeCount: 2,
  randomAttributeSlots: [
    { index: 1, value: 81, label: "随机属性1" },
    { index: 2, value: 81, label: "随机属性2" }
  ],
  availableSecondaryTypes: ["crit", "haste", "mastery", "versatility"]
}
```

后续小程序配装交互在装备加入前读取该字段，让用户选择具体副属性，再把选择结果落到装备快照的 `stats.secondary`。

## 输出

`cos-upload/data-4.4.x` 包含：

- 13 个职业 JSON 和 JS；
- `overview.json` 和 `overview.js`；

- overview 增加制造业注入摘要；
- 每个职业 meta 增加制造业装备数量。
