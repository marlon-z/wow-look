# 12.1 S2 纯本地数据版设计

## 目标

让 12.1 S2 的装备查询、配装模拟器、制造业随机属性、收藏、分享和装备详情完全使用小程序代码包内的数据与图片，不产生 COS 数据或资源下载流量，且用户可见功能与当前版本保持等价。

## 数据边界

发布数据来源固定为 `cos-upload/data-12.1-s2-crafted-preview`。生成器仅移除小程序未消费的采集审计字段：`tooltipRaw`、`dropVersion`、`captureStatus`。保留完整的职业、专精、副本、首领、装备、最高装等、属性、白字、特效、插槽、唯一装备、来源、物品链接和制造业随机属性字段。

公共总览、Logo、缩放后的职业横幅/徽记，以及唯一的装备图标目录均置于主包；13 个职业数据分别置于职业分包。每件装备仍使用独立的本地 WebP 图标，按 24px、质量 35 生成，不使用精灵图或坐标裁切，因此页面图标映射与现有显示逻辑不变。职业选择页只使用主包徽记，进入职业后先加载对应分包。微信质量扫描按所有代码包的图片/音频总量合计，因此生成器强制总媒体小于 200 KiB，主包小于 1.5 MiB。生成依赖为开发期的 `sharp`，由根目录 `package.json` / `package-lock.json` 锁定，不进入小程序代码包。

## 加载行为

`class-data` 保持 `loadOverview()` 与 `loadClassData(classKey)` 的既有异步接口，避免页面逻辑修改。它们从本地精简数据模块返回 Promise；通过 `wx.loadSubPackage` 先加载对应职业分包，再以微信分包异步化的 `require.async` 读取职业数据。数据加载失败时返回 `null`，保持现有页面错误处理语义。

类视觉资源改为主包本地资源路径。所有装备 `iconAsset` 指向主包中的本地图标路径。禁止小程序运行期以 `wx.request`、远端图片 URL 或 COS 域名获取 12.1 数据与本次使用的资产。

## 非目标

不接入 WCL 实时数据；现有赛季未开放提示保持不变。不移除项目外的 COS 上传归档，也不修改游戏插件、导出脚本或用户未提交的 KeystoneLoot 工作。

## 验证

生成器测试对比源数据与本地数据：13 职业、实例/首领/装备记录、关键物品字段、制造业字段、最大装等与图标均完整保留。结构测试确认本地加载器没有 `wx.request` / COS URL，五个分包存在且每包低于 2 MiB。现有小程序更新、制造业和 WCL 测试必须通过。
