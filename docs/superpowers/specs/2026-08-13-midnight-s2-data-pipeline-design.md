# Midnight S2 数据管线设计

## 目标

为《至暗之夜》12.1（Build 69273）与 S2 建立新的正式数据集。小程序上线后只读取 S2；既有 S1 文件既不覆盖也不在客户端暴露，历史清理由产品负责人手动执行。

## 范围

本次覆盖小程序已有的 PvE 范围：当前赛季 Mythic+ 地下城、当前赛季团本、职业套装、制造业装备与 WCL 配装预设。新 Lair 不混入现有“地下城/团本”模型，留待单独设计。

S2 赛季内容使用游戏内冒险指南作为装备、掉落关系和实际说明框数值的唯一真值。外部资料仅用于定位版本范围与准备验证，不会覆盖客户端采集结果。

正式范围的固定验收基准如下。普通装备插件必须从当前赛季页面识别到 8 个地下城：Altar of Fangs、Murder Row、Den of Nalorakk、The Blinding Vale、Voidscar Arena、Kings' Rest、Ruby Life Pools、Temple of Sethraliss；识别到 1 个团本 The Venomous Abyss，且其中有 8 个首领。套装导出必须包含既有的 13 个职业 key 和每个职业 9 件套装外观件。客户端显示的本地化名称不作为硬编码比较字段，实例 ID、首领 ID、职业 key 和装备数才是验收依据。

## 版本与数据目录

新增数据版本常量 `12.1-s2`。转换输出使用 `cos-upload/data-12.1-s2/`，WCL 输出使用 `cos-upload/wcl-presets/data-12.1-s2/`。小程序的单一读取配置切换至该版本；不添加版本选择界面或 S1 回退路径。

正式上传前，所有职业 JSON、overview、图标引用和 WCL 路径必须指向新版本。旧 `data-4.4.x` 不被本次工具删除。

## 游戏内采集

三个插件升级到 12.1 接口并保留明确的赛季配置边界：

- 普通装备插件仍动态识别当前赛季地下城与英雄团本，但 S2 最高装等规则按来源、槽位和尾二/尾王特殊规则验证。
- 套装插件导出 13 职业的新套装，并校验每职业的核心五件与四件外观补充件。
- 制造业插件按 S2 的客户端实际最高制造结果验证，不接受仅修改目标装等但未通过 tooltip 校验的物品。

由于公开资料不能可靠提供客户端 Bonus ID，新增预检导出流程。预检只输出客户端读取到的实例范围、实际链接、装等、轨道文字与诊断信息，不能被转换或上传为正式数据。预检结果用于写入并测试最终 S2 规则；规则确认后再运行正式采集。

预检契约如下：

- `WoWLookExport3` 写出 `mode = "preflight"`、`clientBuild`、当前赛季实例 ID/顺序、首领 ID、每件掉落的原始 hyperlink、tooltip 物品等级和升级轨道文字；
- `WoWLookTierExport` 写出 `mode = "preflight"`、`clientBuild`、13 个职业 key、每职业核心/外观 item ID、每件原始 hyperlink、套装效果 tooltip；
- `WoWLookCraftExport` 写出 `mode = "preflight"`、`clientBuild`、候选配方/装备 ID、普通与特殊槽位的实际预览 link、tooltip 物品等级和扫描诊断。

转换器只接受 `mode = "final"` 的三个导出文件；遇到 `preflight`、缺少 `clientBuild` 或三份文件 Build 不一致时立即失败。预检文件只供生成和审阅规则 manifest，不能被 COS 上传脚本选中。

规则 manifest 是一个受版本控制的 S2 配置单，记录 `schemaVersion`、`dataVersion`、`clientBuild`、赛季标签、8 个地下城实例 ID、剧毒深渊实例 ID 与其 8 个首领 ID、地下城/团本最高装等规则、各轨道 rank/Bonus ID、尾二/尾王与稀有物品的特殊规则、Voidforge 的适用槽位和 Bonus ID、制造业普通/特殊槽位规则、套装 13×9 的 item ID。它必须由预检数据和客户端 tooltip 交叉验证，并和三份插件配置的规则逐项一致，才可将模式改为 `final`。正式转换会比较导出 scope 与 manifest 的实例/首领 ID 集合；少一个、多个或不同 ID 都失败，从而拒绝误识别的赛季。

普通装备插件继续以“地下城史诗、团本英雄”作为稳定的冒险指南发现入口：英雄团本入口只负责建立掉落关系与读取客户端源版本，绝不是正式输出的装等口径。正式输出的每件地下城装备按 manifest 的 S2 地下城最高档规则重建并验证；普通团本装备按 Myth 6/6 规则重建并验证；manifest 指定的尾二、尾王和符合稀有条件的团本物品按其 S2 Myth 9 特殊规则重建并验证。源版本、重建目标、匹配的规则名称、最终链接和 tooltip 装等都保留在导出中，供转换器逐件复验。

## 验证与故障处理

数据转换保持失败关闭：任何缺失的 S2 赛季配置、无效最高档链接、未完成职业分类或 tooltip 不匹配都会使转换失败。不得回退使用 S1 数据或基础物品模板。

自动测试将覆盖：

- 三个插件的 TOC 接口和版本配置；
- S2 数据目录、WCL 远程路径与小程序唯一数据版本；
- 预检数据禁止进入正式输出；
- 正式导出中的最高装等、特殊来源和职业套装完整性；
- 当前配装模拟器在 S2 等级/属性参数未确认前不伪造计算结果。

在等级换算、基础属性与精通系数完成客户端验证前，S2 小程序中的配装汇总计算将禁用并显示“正在适配 S2 属性规则”；装备选择、收藏和详情展示仍可用。验证后的参数必须同样写入规则 manifest 和自动测试，才可重新启用计算。

WCL 生成器必须使用 S2 的赛季/API 参数，并在 `index.json` 写入 `dataVersion`、`clientBuild`、生成时间和内容类型。前端仅加载匹配 `12.1-s2` 的 WCL index；文件缺失、版本不符或没有有效预设时显示“WCL S2 预设暂未生成”，不得读取 S1 路径或本地回退数据。

## 上线流程

1. 发布升级后的插件到游戏安装目录。
2. S2 冒险指南开放后运行预检并提供三个 SavedVariables 文件。
3. 根据预检的客户端真值填写规则，运行测试并发布正式插件。
4. 使用正式插件采集普通掉落、套装与制造业。
5. 转换、校验、审阅 S2 JSON，并上传至独立的 COS staging 前缀。完整性检查确认 13 份职业 JSON、overview、全部图标引用和 WCL index 均可读取后，才将文件复制/上传至 `data-12.1-s2` 与 `wcl-presets/data-12.1-s2` 正式前缀。
6. 只在正式前缀完整且 COS HEAD/HTTP 检查成功后部署小程序读取路径切换。新前缀避免旧缓存污染；上传未完成、缺少关键 JSON 或任一校验失败时保持当前小程序版本不变，不发布半成品。
7. 打开小程序检查八个 S2 地下城、剧毒深渊、套装、制造业和 WCL 请求均来自 S2 路径；WCL 暂未生成时仅显示不可用提示。
8. 由产品负责人自行清理 COS 或本地的 S1 文件。

## 实施边界

| 单元 | 责任 | 主要位置 |
| --- | --- | --- |
| 普通装备插件 | 12.1 加载、预检/正式模式、最高装等与特殊来源验证 | `addon/WoWLookExport3/` |
| 套装插件 | S2 套装入口、预检/正式模式与 13 职业完整性 | `addon/WoWLookTierExport/` |
| 制造业插件 | S2 制造业预检/正式验证 | `addon/WoWLookCraftExport/` |
| 规则与转换器 | manifest 校验、拒绝预检文件、生成 S2 JSON | `scripts/`、`cos-upload/` |
| WCL 管线 | S2 标识、生成与 COS 上传前缀 | `scripts/wcl-*`、`.github/workflows/` |
| 小程序 | 唯一 S2 数据/WCL 路径、计算降级提示 | `miniprogram/utils/`、`miniprogram/pages/` |
| 自动测试 | 配置、版本、导出和前端路径门禁 | `tests/`、`scripts/test-*.js` |
