# 配装模拟器绿字百分比版本更新验证说明

## 一、目的

每次魔兽世界大版本、赛季、等级上限或装备数据更新后，必须重新验证配装模拟器的暴击、急速、精通、全能百分比。不能因为装备等级分汇总正确，就默认百分比换算仍然正确。

本说明适用于小程序配装模拟器。当前基准版本为：

- 游戏版本：`12.0.7`
- 角色等级：`90`
- 装备数据版本：`4.3.x`
- 统计范围：包含装备属性和职业/专精固定基础值；不包含种族、天赋、附魔、宝石、食物、合剂及临时 Buff

## 二、当前计算基准

| 项目 | 12.0.7 / 90级基准 |
|---|---:|
| 1%暴击所需等级 | 46 |
| 1%急速所需等级 | 44 |
| 1点精通所需等级 | 46 |
| 1%全能所需等级 | 54 |
| 通用基础暴击 | 5% |
| “致命一击”专精基础暴击 | 10% |
| 基础急速 | 0% |
| 基础精通 | 8点 |
| 基础全能 | 0% |

拥有额外5%“致命一击”被动的专精：

- 浩劫、复仇恶魔猎手
- 野性、守护德鲁伊
- 全部猎人专精
- 酒仙、踏风武僧
- 全部盗贼专精
- 增强萨满

护甲专精增加的力量、敏捷、智力或耐力不属于四项绿字，不参与本公式。

## 三、递减曲线

递减只作用于等级分换算出来的部分，不作用于5%/10%基础暴击和8点基础精通。

| 原始百分比或精通点区间 | 本区间收益 |
|---|---:|
| 0～30 | 100% |
| 30～40 | 90% |
| 40～50 | 80% |
| 50～60 | 70% |
| 60～80 | 60% |
| 80～200 | 50% |
| 200以上 | 0% |

对应的原始输入→递减后输出节点：

```text
30 → 30
40 → 39
50 → 47
60 → 54
80 → 66
200 → 126
```

不能把输出节点 `39/47/54/66/126` 当作下一次计算的输入分界线。

## 四、版本更新时必须重新确认的项目

更新装备数据前，记录新的游戏版本、客户端 Build、等级上限和数据目录版本，然后逐项确认：

- [ ] 新等级下暴击、急速、精通、全能的等级换算常数
- [ ] 二级属性递减曲线及硬上限
- [ ] 通用基础暴击是否仍为5%
- [ ] “致命一击”被动的数值及适用专精列表
- [ ] 基础精通是否仍为8点
- [ ] 所有专精的精通系数和主要显示效果
- [ ] 是否新增直接修改绿字或等级收益的职业固定被动
- [ ] 小程序备注中的排除项是否仍与计算范围一致

仅更新装备库、但等级上限和公式没有变化时，也必须运行自动测试并至少完成一次游戏内抽查。

## 五、数据来源优先级

按以下顺序确认，不能只依赖旧文档：

1. 游戏内角色面板及暴雪客户端 API 实测
2. 当前客户端 DBC/Curve 数据
3. SimulationCraft 对应正式服分支生成数据
4. Wowhead 当前正式服法术数据
5. 社区攻略只用于交叉验证

版本更新时需要保存来源链接、Build 和查询日期。旧版本文章不能直接沿用。

## 六、游戏内对照方法

### 6.1 测试环境

- 使用满级角色，退出战斗并清除临时 Buff。
- 不使用食物、合剂、团队增益和临时触发效果。
- 记录角色职业、专精、种族和当前天赋。
- 小程序不计算种族和天赋；游戏对照值中存在这些加成时必须先扣除，或更换无相关加成的测试角色/天赋。
- 游戏装备必须与小程序所选装备一致；附魔和宝石需要移除或从游戏数值中扣除。

### 6.2 游戏内API对照

游戏内可使用以下接口读取未取整数据：

```lua
GetCombatRating(CR_CRIT_MELEE)
GetCombatRatingBonus(CR_CRIT_MELEE)
GetCritChance()
GetHaste()
GetCombatRating(CR_MASTERY)
GetMastery()
GetMasteryEffect()
GetCombatRating(CR_VERSATILITY_DAMAGE_DONE)
GetCombatRatingBonus(CR_VERSATILITY_DAMAGE_DONE)
GetVersatilityBonus(CR_VERSATILITY_DAMAGE_DONE)
```

全能面板值应按以下方式对照：

```lua
GetCombatRatingBonus(CR_VERSATILITY_DAMAGE_DONE)
  + GetVersatilityBonus(CR_VERSATILITY_DAMAGE_DONE)
```

### 6.3 最低抽查组合

每次版本更新至少验证：

1. 一个5%基础暴击专精，例如织雾武僧。
2. 一个10%基础暴击专精，例如踏风或酒仙武僧。
3. 一个力量专精。
4. 一个智力专精。
5. 至少三个精通系数差异明显的专精。
6. 一套未达到30%递减线的装备。
7. 使用人工测试等级分验证全部递减节点。

## 七、通过标准

| 对比项 | 允许误差 |
|---|---:|
| 四项等级分合计 | 必须完全一致 |
| 暴击、急速、全能API百分比 | ±0.01个百分点 |
| 精通API百分比 | ±0.02个百分点 |
| 游戏面板取整值 | 必须与相同取整规则后的结果一致 |

任何专精超出误差都不能通过版本验收。必须确定差异来自换算常数、递减、专精被动、精通系数还是被排除的种族/天赋/Buff。

## 八、自动测试门禁

每次更新装备数据或绿字公式后执行：

```powershell
node tests/test-stat-calc.js
node tests/test-weapon-rules.js
git diff --check
```

`tests/test-stat-calc.js` 必须至少覆盖：

- 5%与10%基础暴击专精
- 急速和全能0%基础值
- 8点基础精通
- `30/40/50/60/80/200`全部递减节点
- 基础值不参与递减
- 主属性不加入统一的角色裸装值
