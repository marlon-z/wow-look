# 制造武器与饰品295导出设计

## 目标

在现有制造装备导出流程中增加特殊栏位规则：武器、饰品、盾牌和副手法器导出经游戏验证的295版本，其余制造装备继续导出285版本。候选发现、随机属性解析和现有小程序数据均不改变。

## 已验证数据

当前赛季普通制造装备使用以下公共 Bonus ID，最高品质说明框为285：

```text
12214, 13667, 12497, 12066, 13622
```

武器实物链接及合成链接证明，特殊栏位使用以下公共 Bonus ID，最高品质说明框为295：

```text
12214, 13655, 12497, 12066, 13640, 13622
```

合成链接已经分别验证：武器、饰品、两件盾牌和副手法器均可读取为295。盾牌 `244472` 首次查询返回空值，经提示框预加载后再次查询为295，说明这是链接缓存问题，不是职业无法装备盾牌。

实物链接中的绿字选择、美化、附魔、宝石、制造者和角色信息不属于通用模板，不复制到导出链接。

## 栏位规则

295特殊栏位包括：

- `INVTYPE_TRINKET`
- `INVTYPE_WEAPON`
- `INVTYPE_2HWEAPON`
- `INVTYPE_WEAPONMAINHAND`
- `INVTYPE_WEAPONOFFHAND`
- `INVTYPE_SHIELD`
- `INVTYPE_HOLDABLE`
- `INVTYPE_RANGED`
- `INVTYPE_RANGEDRIGHT`
- `INVTYPE_THROWN`

其他支持的战斗装备栏位使用285规则。

当前98件制造装备中，预期28件使用295规则：20件武器、5件饰品、2件盾牌、1件副手法器；其余70件保持285。

## 数据流程

1. 扫描订单系统，并以最高 `iLvlMin` 动态识别当前赛季候选。
2. 获取候选配方最高制造品质的基础链接。
3. 保留基础链接的制造品质和随机属性 modifier。
4. 根据 `equipLoc` 选择285或295公共 Bonus ID。
5. 使用 `C_Item.GetDetailedItemLevelInfo` 和说明框解析验证最终装等。
6. 验证成功后写入正式 `items`，并记录目标规则、目标装等和公共 Bonus ID。

## 缓存与失败策略

特殊链接首次无法读取时，先调用提示框接口触发加载，再延迟重试。重试次数必须有限，避免扫描卡死。

295验证仍失败时，不删除该装备，也不伪造295结果；改用已经验证的285链接作为安全回退。285链接也无法验证时，保持 `configured_maximum_unverified`，不进入正式数据。

## 配置结构

`SeasonConfig.lua` 分开保存：

- 普通目标装等与普通公共 Bonus ID；
- 特殊栏位目标装等与特殊公共 Bonus ID；
- 特殊栏位集合；
- 链接加载重试次数和延迟。

下赛季只需更新配置并重新进行游戏内验证，不在扫描逻辑中写死起始装等或物品 ID 白名单。

## 验收标准

- 当前赛季扫描仍只处理98件 `246+` 候选；
- 28件特殊栏位装备全部经说明框验证为295；
- 70件其他装备全部经说明框验证为285；
- 1条和2条随机属性数量及数值保持正确；
- 不复制实物绿字、美化、附魔和宝石；
- 首次缓存未命中能够重试；
- 295失败时回退285，285失败时保持待验证；
- 不修改小程序和其他装备导出插件。
