# 4.3.x 装备数据升级设计

## 目标

将游戏客户端最新生成并通过最高装等验证的 `WoWLookExport3.lua` 纳入项目，生成独立的 `cos-upload/data-4.3.x` 数据集。保留现有 4.2.x 数据，不修改网站、小程序、SEO 或远程 COS 配置。

## 输入

- 普通装备：`E:/World of Warcraft/_retail_/WTF/Account/513648058#1/SavedVariables/WoWLookExport3.lua`
- 职业套装：项目根目录 `WoWLookTierExport.lua`
- 转换器：`scripts/parse-export.js`

最新普通装备输入必须满足：插件版本 `3.3.3`、373 条最高版本全部成功、虚空铸造和固定团本 298 链接验证通过。

## 输出

创建 `cos-upload/data-4.3.x`：

- 13 个职业各一份 JSON 和 JS；
- `overview.json` 与 `overview.js`；
- 每份数据的版本统一为 `4.3.x`；
- `addonVersion` 保持输入数据的 `3.3.3`；
- 保留职业套装实例与现有共享图标路径。

## 转换器调整

当前新导出模式忽略 `--data-version`，直接把游戏 Build 字符串写入 `version`。调整 `buildClassPayload` 和 `buildOverviewPayload`，在提供 `--data-version 4.3.x` 时将其写入 `version` 和 `dataVersion`；未提供参数时保持现有行为。

## 数据流

1. 将客户端 SavedVariables 复制到项目根目录并替换旧 `WoWLookExport3.lua`。
2. 先在临时输出目录运行转换器，输入普通装备和职业套装文件。
3. 验证文件数量、版本、职业、实例、最高装等状态和代表性虚空铸造装备。
4. 验证通过后生成正式 `cos-upload/data-4.3.x`。
5. 保留 `cos-upload/data-4.2.x` 不变。

## 验收标准

- 根目录原始导出与客户端文件 SHA256 一致；
- `cos-upload/data-4.3.x` 包含 28 个文件；
- 13 个职业 JSON/JS 成对存在且可解析；
- 所有文件数据版本为 `4.3.x`；
- 普通装备元数据来自插件 `3.3.3`；
- 每个职业保留职业套装实例；
- 物品 `258514` 在适用职业数据中为 298，链接包含 `12701` 和 `13654`；
- 未修改网站、小程序和 SEO 的 4.2.x 配置。
